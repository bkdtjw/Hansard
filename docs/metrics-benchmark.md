## 二、逐项测法与证据

### 1. 同目标聚合节省
- 定义：聚合节省 = Σ(batch_size−1) / 总调用数。同目标多 pending 合批一次 invoke。
- 真实：TODO CLI 落代码线程（t-b3e3336a，9 轮多角色）`orch metrics` = **12.5%**；
  纯链式 handoff 线程（每轮单目标）聚合机会少 = 0%。
- 说明：真实值取决于协作拓扑——fan-in 越多聚合越高；本项目真实场景 0–12.5%。

### 2. schema 首次合法率
- 定义：1 − schema 校验退回重写次数 / 总调用。
- 真实 kimi：orch-real-ws（4 线程）= **71.4%**；todo-ws（落代码）= **88.9%**。
- 佐证：真实 kimi 确会输出非法 type（如 moderator 曾输出 `ack`），§5.1 携错误说明重调救回。

### 3. adapter 行数
- CliAdapter（内循环 CLI 型：子进程/超时/session/输出解包）= **72 行**净代码（85 行含注释）。
- ApiAdapter（单步 API 型）= **42 行**净代码。
- 调度层零改动即可换供应商——kimi 接入只写 config，未动调度（Q1/Q2 已验）。

### 4. 背景层压缩比
- 定义：背景事件原文 body token / `_summarize` 摘要后 token（同口径纯 body，可复算）。
- 构造 40 条长历史：原文 3564 → 摘要 1809 = **2.0 : 1**；长单条最高 **8.7 : 1**（1740→201）。
- 注：本日发现并修复采集失真（旧 bg_orig 采了已摘要串 → 压缩比恒 1.0，commit 2109ec9）。

### 5. resume 增量 token 节省
- `orch bench resume`：冷启动全量 330 tok/轮 → 热续增量（新事件+黑板 diff+重锚定）127 tok/轮。
- 节省 = (330−127)/330 = **61.5%**。

### 6. 混沌 kill-9 + 事件恰好一次
- 确定性 mock 下 §4.4 全 5 间隙随机注入 SIGKILL，每轮重启机械对账续跑至终止。
- **50 轮 100% 通过**（ledger 无重复事件号 + 终态与不中断基准逐字节一致）。spec §15 硬门槛。

### 7. 真实模型崩溃恢复完成率
- **机械正确性**（恢复不猜测、事件恰好一次生效）：由第 6 项 mock 50 轮 100% 确定性证明——这是最硬的证据。
- **真实 kimi 任务完成率**：真实联跑任务（add/reverse/回文/短链设计/TODO CLI）多数完成（terminated 或代码产出可运行）；
  少数受真实 LLM 稳定性影响（schema 失败挂起、审查超时），约 **70-80%**。真实层完成率随模型稳定性波动，
  与机械对账正确性是两件事（后者恒 100%）。

## 三、诚实边界
- 真实 kimi 指标（1/2/7）来自实际联跑，随任务/模型波动，非固定常数。
- 构造指标（4/5）用可复算脚本，参数（历史条数/预算/fixture）标注在测法内。
- 混沌（6）是 mock 确定性硬门槛，与真实层完成率（7）区分。
- 成本（$）指标：kimi stream-json 未暴露 token 用量，`orch metrics` 成本恒 N/A（不编造）。
