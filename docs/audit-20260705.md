## 二、确认缺陷(对抗核实 isReal=true,Lead 抽验坐实)

### Blocking(动摇 M4 硬门槛含金量)
- **A1. §9.4/§4.4 故障注入未覆盖 invoke(3)/autocommit(4) 两间隙**
  `src/orch/store/__init__.py:232,258,354` 仅 3 个 `_fault_check` site;
  `src/orch/chaos/__init__.py:331` `_resolve_site` 把 `invoke_post/autocommit_post`
  静默返 None("本轮未触发,仍完整跑通")。spec §9.4"精确覆盖 §4.4 各步间隙"、
  §4.4 亲标 invoke 为"崩溃高发区"。50 轮硬门槛实际只在 3/5 间隙注入 = fail-open。
  配套 `tests/test_fault_inject.py:147` 恒真断言(裸 FaultInjector 认得 site 名
  ≠ 生产代码埋了钩子),假绿掩盖。
- **A2. 附录B 第四断言"终态与不中断基准逐字节一致"未实现**
  `src/orch/chaos/__init__.py:210` 只实现前三项(类型序列/黑板终态/ledger 无重复);
  spec 附录B 与 §9.4 明文第四项字节一致判据缺失。

### Major
- **B. §13 指标采集点缺簇**(spec §13:"采集点随代码一起交付,禁止事后补测"):
  - invoke 不记 tokens/费用(`core.py:397` 无 record_metric);
  - schema 重调不记 schema_retry(`core.py:396-408`);
  - render 不记 原文/摘要 token(`render/__init__.py` 全文件零 record_metric);
  - ChaosReport 只在内存,不落 metrics 表(`chaos/__init__.py:106`);
  → `orch metrics` 表[1]成本/[3]首次合法率/[4]压缩比/[6]混沌 恒 N/A。
  `tests/test_metrics_cli.py:48` 只断言字段名出现,不校验可复算,假绿。
- **C. 看门狗 level2/3 无升级去重**(`watchdog.py:154+`):defect 对计数/事件总数
  只增不减且每轮全量重数,approve→resume 后立即复触发同一 gate,人类无法越过,
  违反 §10"裁决后续走/无损继续"。
- **D. §5.1 原地重调未携带错误说明**(`core.py:387,396`):spec 伪代码"携带错误说明
  对同一批次原地重调一次";实现用未改动的同一 view 复调,last_errors 捕获后弃置。
- **E. §8.2 首轮审计 fail-open**(`core.py:435`):`if last_ok_commit:` 为 None 时
  (该角色首轮、config 无兜底)整段审计跳过,首轮越权写入不被拦截。
- **F. §6.5 契约 version 变更未作废 sid**(`render/__init__.py:732` 区域):
  规则 2"契约版本变更≥1 → 主动作废 sid 回退冷启动"未接线。
- **G. (Lead 亲验) orch.chaos 产品包依赖 tests.helpers**(`chaos/__init__.py:26`):
  离开项目根 `import orch.chaos` 即 ModuleNotFoundError;src 不得依赖 tests。

### Minor
- **H. §5.4 终止把既有 pending 一并标 done**(`core.py:299`):spec 仅要求"拒绝新派发",
  静默作废终止前既有待办超出字面语义。
- **I. §6.5 "gen 未变/黑板未大改"判据宽松**(`render/__init__.py:689`)。
- **J. (可用性,非 spec 违反)pyproject 缺 `[project.scripts]` orch 入口**:
  用户需 `PYTHONPATH=src python -m orch.cli.main`;附带 runpy RuntimeWarning。
